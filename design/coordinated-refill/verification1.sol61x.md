## Interfaces and lifetimes

| Command | Contract |
| --- | --- |
| `renewal init ROOT --candidate JW --candidate-provenance JSON [--jj ELF --git ELF]` | ROOT must be new. Preserve the candidate/sidecar, create one owned donor and two native receiver roots once, construct D in receiver A, pin S/D/O independently, and retain setup/raw native records. No remote, donor import, builder or renewal command. |
| `renewal accept ROOT OUTPUT` | OUTPUT must be new. Check real candidate help before reset, then reset and verify all four positive shapes for each route. Retain every process/raw report even on failure. Only fully validated actual report evidence could produce a passing acceptance receipt. |
| `renewal sample ROOT OUTPUT --acceptance RECEIPT --case CASE [--timing native\|instrumented --seed 1701]` | Require bound successful acceptance before output/reset/performance. Native: exactly four mirrored commands. Instrumented: two separate count probes. No default measured matrix, warmup, significance claim or throughput inference. |

One original saved candidate path executes **both** route choices. The shared
engine's per-label copies are archival, byte-identical to it. Build sidecar hash,
full immutable application/library source IDs, actual compiler/profile/features,
input hashes and build environment are preserved unchanged from `jw-perf build`.
The existing guard is not replaced or relaxed.

Every invocation is literal argv, from the owned donor:

```text
JW reseed worker-a [worker-b] --from OWNED_SOURCE \
  --source-at 'commit_id("S")' --at 'commit_id("D")' \
  --renewal-route=clear-then-populate|replace-authorized --format=json
```

There is no `--replace-content`, `jj edit`, `.jj` copy, blanket `TMPDIR`, shell
expansion, remote access or automatic reconciliation. Native reset operations are
named `new`, `status` and preservation bookmarks. Ordinary resets use strict
`cp -a --reflink=always` plus a closed set of named small deltas. Preflight refuses
unknown Q entries or changed directory/link/file route kinds before deleting any
named ordinary leaf. The first failed measured attempt halts later resets/commands,
even though the shared runner retains refusal rows for remaining schedule slots.

## Fixtures and external oracles

The four shapes are `clean-n1`, `paired-n2`, `mixed-n2`, `desired-n2`:

- Clean N1: O's tracked tree equals S; Q is byte/stat-equal. External verification
  requires ordinary file inode/mtime retention. Required tracked renewal still
  needs **actual successful report clone counts**, not inode-change inference.
- Paired N2: lane A changes one small interior leaf; lane B changes a different
  leaf. Both contain distinct stale selected leaves.
- Mixed N2: A has no Q at all; B has paired Q plus stale content. The future report
  binding must distinguish opaque population from paired-source sharing.
- D≠S: fixed independent pins; modified/added/removed leaves, both directory/file
  transition directions, changed literal symlink and executable mode. Final-D
  storage is not equated with temporary S installation: D-only, changed and native
  restored leaves may come from the native store.

The source has **seven tracked regular-file obligations plus one literal link**.
Source Q contains two tiny files and one link. Every case preserves unrelated
`.env` and target `vanished/keep` while the selected source root is absent.

Matched start signatures contain tree bytes/kinds/modes/regular-file mtimes, S/D,
and lane shapes, but deliberately not receiving inode/new-WC identities. Each
attempt creates its own native child; exact old commits and covering bookmarks
are recorded separately. Verification checks stable root/`.jj`/repository object
identities and pointers, registrations/names, pinned history, unchanged donor,
full sparse, exact D, conflict-free empty single-parent child with a new change,
physical files/types/modes/links, Q convergence/stale removal, private regular
objects and a bounded restored write-isolation probe. These are not extent-range
measurements or native-protocol approval.

All ordinary checkout entries—including structural dirs, ignored controls and
links—are inventoried. Two entire donor-content copies are conservatively reserved
for staging. The hard aggregate ceiling is **256 entries / 1 MiB**, with artifacts
and native administration outside that ordinary count. The single setup/reset
smoke's maximum calculated bound was **84 entries / 1,018 bytes** including that
reserve; no production staging maximum is claimed.

## The deliberate blocker: actual public report fields

[`report_evidence`](/tools/performance/src/renewal/mod.rs) currently returns a
specific error for **every** JSON value. It must remain fail-closed until the actual
public CLI exists. `accept` cannot pass, and `sample` re-extracts every raw accepted
report before execution, so a `passed: true` flag cannot bypass this seam. A help
string, zero process exit or callable `refill_one` result is never route acceptance.

Later Sol should implement this one seam against the reviewed wire contract:

1. Validate actual public command/schema/status, selected route and admitted native
   profile/raw JJ build, exact reported S and D and the intended receiver cohort.
2. Require every receiver complete, native membership coverage complete and final
   finish success; retain actual partial/error information on failure. Check seven
   successful source regular clones per receiver and zero successful byte copies.
   Do not substitute obligation counts for successful effects.
3. For clean N1 require actual zero ordinary writes; for heterogeneous N2 retain
   actual paired acquisition/sharing and opaque work separately. If those fields
   are absent, identify the missing instrumentation rather than inventing counters.
4. Preserve reported wall/setup/native/install/ordinary/finish timings **only where
   available**. Missing fields stay unavailable/null, never zero. Do not derive
   tracked-install time by subtraction, sum overlapping lane durations into cohort
   wall, or call wrapper start timestamps subprocess duration.
5. Return the adapter's validated evidence while retaining the complete original
   stdout file. Add parser discriminators for wrong route/cohort/pins, partial rows,
   missing clone/copy/phase counters and the actual lossless large-integer encoding.

Failure process status and stderr are preserved **before** attempting JSON parsing.
Non-JSON failure stdout cannot mask the original exit, signal, timeout or stderr.
Setup/reset/hash/verification and artifact-guard costs remain outside measured
process wall time; process CPU/RSS and literal raw argv/cwd remain accessible.
Instrumented traces contain only the actual public command's PATH-observed JJ/Git
children, not the adapter's setup/verification calls. Absolute child paths can
still bypass wrappers, as documented by the existing tooling.

This comparative positive gate does not replace the broader
[accepted semantic requirements](execution0.gpt6a.md#10-cost-ledger-and-bounded-evidence):
parent must first run actual production authority/retained-descendant, second-lane
native/provider/finish failure, final-only producer, preview and continuation gates.
No such tests or protocol results are claimed in this tooling slice.
